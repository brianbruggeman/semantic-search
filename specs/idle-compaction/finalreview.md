# idle-compaction revised source review

Source review only; no builds or runtime observations were made.

## Remaining findings

1. **Quiet-at-start sampling can miss work that has already entered.** `ss/src/daemon.rs:868` reads the active counters before reading the epochs at line 869. `Core::begin_activity` increments `active_work` first, then the epoch (`ss/src/daemon.rs:126`); `NativeCall::begin` uses the same ordering (`ss/src/embed.rs:276`). An interleaving can read quiet, then start work and increment its active counter, pause that work before its epoch increment, and read the old epoch in the blocking task. The task then starts with active work despite the matching epoch. This concerns work already admitted before the start snapshot, not the expressly permitted arrival after maintenance starts. A coherent admission/snapshot protocol must also preserve the specification's prohibition on holding foreground requests behind the merge.

2. **The AC0 shared-oracle requirement remains unexercised.** `specs/idle-compaction/SPEC.md` AC0 requires the same assertions to accept the direct authored-row/ownership/rg incumbent and reject missing-row, live-work, and empty-path controls. `ss/src/store/vector_cache.rs:514` runs separate assertions on rg output, a channel, and `List::top`; it does not run a shared assertion over an actual maintenance result and those controls. The empty-directory check at line 528 is now present. The actual attempt fixture at `ss/src/daemon.rs:1039` verifies held request and native ownership independently, but does not supply the stated shared oracle. The per-epoch test at line 1085 still exercises `maintenance_due` directly rather than the monitor across epochs.

## Prior finding dispositions

- Exclusive maintenance admission: withdrawn under the clarified R2 and architecture in `specs/idle-compaction/SPEC.md`. New work after maintenance starts must remain admitted, with no global gate holding foreground requests behind merge. `ss/src/daemon.rs:867` now rechecks before merge, subject to the snapshot race above.
- Native dequeue gap: the queued job owns `JobLease` from before `send` (`ss/src/embed.rs:595`) until the job is dropped (`ss/src/embed.rs:199`), and `is_idle` checks the inflight count at line 428. The active native guard covers warm-up and model loading/call at lines 494 and 527, and releases on unwind through `Drop` at line 287.
- Panic-held compaction flag: the background worker now owns `CompactionLease` before calling `compact` (`ss/src/store/vector_cache.rs:330`); its `Drop` resets the flag at line 341. The idle path also owns the lease at line 400. Thread-spawn failure resets the flag at line 334.
- Pending candidate consuming an epoch: `ss/src/store/vector_cache.rs:394` returns `Pending` for a held flag, and `ss/src/daemon.rs:837` records the epoch only when pending roots are zero. A blocking-worker failure is logged and returns no completion at line 893.
- Held-reader payload assertion: `ss/src/store/vector_cache.rs:553` now checks both the merged IDs and matrix and the held view's IDs and matrix. The clean-list fixture checks the same `Arc` remains installed at line 600.
- Allocator ABI: `ss/src/memory_reclaim.rs:14` declares pointer, `usize`, and `usize` return, corresponding to the SDK signature at `/Applications/Xcode.app/Contents/Developer/Platforms/MacOSX.platform/Developer/SDKs/MacOSX.sdk/usr/include/malloc/malloc.h:518`. `ss/src/daemon.rs:867` invokes the pass in a blocking task after `compact_idle` returns. Runtime allocator behavior was not observed in this review.

## Shared activity tracker re-review

The prior incoherent-snapshot finding is withdrawn for the revised source. `ss/src/activity.rs:35` and `ss/src/activity.rs:68` update count and epoch together in one atomic operation; `quiet_epoch` at line 46 reads both from one atomic load. `ss/src/daemon.rs:865` uses that quiet epoch as the start snapshot, with no gate that delays foreground work after that load. `ss/src/embed.rs:555` places a lease in the job before enqueue, and `ss/src/embed.rs:451` covers warm-up with the same shared tracker. The poisoned state at `ss/src/activity.rs:31` and line 64 disables future quiet snapshots on overflow; counted leases do not decrement a poisoned state, which remains ineligible for maintenance.

The payload part of the oracle is now shared between direct authored and actual merged lists (`ss/src/store/vector_cache.rs:513`, lines 567 and 603). The AC0 finding remains for the other controls: path membership and channel ownership are separate assertions at lines 549–563, and the helper is not called with a missing actual row to show it rejects that payload. The epoch fixture at `ss/src/daemon.rs:1078` still exercises the predicate rather than actual maintenance across epochs, and no fixture observed here asserts a foreground arrival is admitted after maintenance begins. No runtime observations were made.
