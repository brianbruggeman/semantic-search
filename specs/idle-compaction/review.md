# idle-compaction source review

Source review of the frozen implementation; no builds or runtime measurements were performed.

1. **Disposition: exclusive admission recommendation withdrawn; start recheck required.** Updated `specs/idle-compaction/SPEC.md` R2 and architecture explicitly permit new work after maintenance starts and prohibit a global gate that holds foreground requests behind merge. The following original observation describes the reviewed snapshot, but its proposed exclusive admission conflicts with that clarified requirement. The revised implementation must recheck the captured epoch and quiet state inside the blocking task before starting, and leave later requests admitted.

   Original observation: `ss/src/daemon.rs:814` samples the epochs and `ss/src/daemon.rs:816` checks active work, then `ss/src/daemon.rs:834` starts a blocking task. `ss/src/daemon.rs:126` and `ss/src/daemon.rs:292` allow request and watcher activity to begin independently at any point, including after that check and throughout the merge and allocator call. `ss/src/embed.rs:516` similarly begins a native call independently. Therefore the sampled quiet state does not establish the clarified R2 quiet-at-start condition after blocking-task scheduling. The idle gate fixtures at `ss/src/daemon.rs:1010` and `ss/src/daemon.rs:1052` call the predicate with sampled values; they do not exercise an arrival between admission and execution or during maintenance.

2. **A dequeued native job is temporarily invisible.** `ss/src/embed.rs:489` removes the job from its queue, while `ss/src/embed.rs:516` increments the native active count only after checking the response and model state. `ss/src/embed.rs:415` declares idle when the counters are zero and both queues are empty, so it can report idle in this interval. A cancelled request can have released its request guard while the worker has already passed the closed-reply check. The worker needs ownership accounting across dequeue and execution, coordinated with maintenance admission.

3. **A background compaction panic leaves its guard set.** `ss/src/store/vector_cache.rs:323` sets the shared flag, but `ss/src/store/vector_cache.rs:331` invokes `compact` before the explicit reset at line 332. An unwind skips that reset. Later normal and idle compactions both refuse the flag at lines 324 and 373, respectively. The RAII lease at lines 339–344 is used only by the idle path; it does not protect the background path.

4. **A skipped dirty list consumes its quiet epoch.** `ss/src/store/vector_cache.rs:373` returns false when another compaction holds the flag, and `ss/src/store/vector_cache.rs:357` reduces those skips to a count. `ss/src/daemon.rs:834` treats the blocking task's successful return as completion, recording the epoch at line 848 regardless of skipped or failed candidates. If the concurrent compaction leaves a newly published dirty segment, no later idle pass occurs without a new work epoch. Completion must distinguish a completed pass from retryable skipped candidates.

5. **The acceptance oracle does not exercise the claimed shared assertions.** `specs/idle-compaction/SPEC.md` AC0 requires the same assertions to accept an authored-row/ownership/rg incumbent and reject missing-row/live-work/empty-path controls. `ss/src/store/vector_cache.rs:488` separately checks an rg path, a channel, and `List::top`, but never runs an actual maintenance pass through a shared oracle or checks an empty-path control. `ss/src/daemon.rs:1010` checks `maintenance_due` while a native call is held, rather than observing whether the maintenance task starts. `ss/src/store/vector_cache.rs:532` holds a reader, but line 540 asserts only its IDs, not its vector payload. These assertions do not establish the acceptance conditions described in the spec.

The macOS declaration at `ss/src/memory_reclaim.rs:12` uses pointer and `usize` arguments and `usize` return, matching the SDK declaration at `/Applications/Xcode.app/Contents/Developer/Platforms/MacOSX.platform/Developer/SDKs/MacOSX.sdk/usr/include/malloc/malloc.h:518`; the call is inside the blocking closure at `ss/src/daemon.rs:834`. The source does not establish a runtime allocator result.
