# Cancellation evidence and mechanism

The client exchange in `ss/src/client.rs` writes one complete frame, flushes it, and reads until its response. It does not half-close its write side. The daemon previously spawned each `answer` task without an owner; after the reader observed EOF, those tasks and admitted lane jobs kept running.

`serve_connection` now owns answers in a `JoinSet` and reaps completed tasks while it continues reading. Read EOF, read error, or outbox writer termination aborts and joins remaining answers. Dropping an answer drops its `submit` oneshot receiver. `work_loop` selects the receiver's `closed()` notification before execution and during an admitted async index or query. The embedding worker checks the queued job's oneshot sender before loading or invoking its model. A native model call already running is allowed to finish its current batch. `index_path` emits a debug start event with both canonical request scope and resolved root.

The two `cost_cancel_` unit fixtures cover a closed admission that must not register an index root and an abandoned embed job held behind a model-owned channel gate. The `cost_disconnect_` integration fixture sends an index frame through a real IPC socket, closes that socket during a gated model call, then completes an empty live index while the native call remains blocked. That completion is the channel gate proving the abandoned async request released the index lane. It then releases the native call and checks that a live client can index and query an independently authored file while the abandoned scope submits no later model calls.

The socket fixture sends a complete frame and drops the connection. A peer that intentionally half-closes only its write side would currently be treated as disconnected by the server's EOF path. The current client does not use that exchange pattern; any future protocol extension permitting it needs an explicit end-of-requests signal or a separate peer liveness mechanism before changing this ownership rule.
